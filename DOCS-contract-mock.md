# Mock test over the relay (kind `mock`, Lane.chat)

A timed paper: 10 Python "what does this print" MCQs, 1 palindrome task, 3
MySQL tasks (joins/aggregation, pivot, dates/number format). One kind, `op`
picks the action. Keys, hidden tests and reference SQL stay on the server
(`<data>/mocks/<id>.json`, newest 20 kept); the phone sees public fields only.

| op | body | result |
|---|---|---|
| `start` | `minutes?` 5..180, default 60 | `mock_id, started_ms, deadline_ms, minutes, notes[], tasks[]` |
| `answer` | `mock_id, task, answer, ts` | `{ok, late}`; replaces the task's answer; `ts` (client ms) > deadline + 90 s = late, ignored |
| `run` | `mock_id, task, answer` | SQL `{ok, error, columns, rows}` (no verdict); code `{ok, examples[]}` (visible examples) |
| `finish` | `mock_id` | `{score, total, percent, finished_ms, tasks[Item]}`, idempotent |
| `get` | `mock_id` | paper + `answers{task: text}` + `result?` (resume) |

Task: `{id, section: py_mcq|py_code|sql, title, topic, prompt_md, code?, options?[4], starter?, tables?, sample?}`.
MCQ answer = option index as text. Item: `{id, section, title, topic, correct, answer?, detail, link?}`;
`link` is `{kind: lesson, topic}` (SQL) or `{kind: coach, slug}` (code), only when missed.

- MCQ key = the snippet's real stdout from `code_runner` (bubblewrap); a snippet
  that errors, hangs or prints nothing is dropped. Fewer than 10 fresh ones are
  topped up from `<data>/mock_bank.json` and the seed bank (`mock_seeds.py`).
- SQL tasks come from `sql_drills` (`sd.run`, exact output); one is generated by the model per start.
- Every `answer` and `run` is a focus heartbeat (`sql_drills` source).
- The phone queues `answer` offline like `focus_event` (rid and `ts` at tap time).
